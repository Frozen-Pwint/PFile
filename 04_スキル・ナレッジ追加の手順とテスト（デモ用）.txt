================================================================
 スキル（Skills）／ナレッジ（Knowledge）追加の手順とテスト（デモ用）
================================================================

■ 同梱ファイル
 knowledge/K1_契約審査ガイドライン（サンプル）.docx   ← 基準に照らした指摘のデモ用（メイン）
 knowledge/K2_比較観点チェックリスト.docx             ← 比較の観点（重要度つき）
 knowledge/K3_社内用語集（サンプル）.docx             ← 社内用語の定義
 skills/pdf-diff-report.zip                          ← スキル①：PDF差分レポート
 skills/exec-summary-5lines.zip                      ← スキル②：経営層向け5行要約

■ A. ナレッジを追加する（約3分）
 手順（Configureタブ）
  1. Configureタブの「Knowledge」セクションを開く
  2. 「Upload」を選び、knowledge フォルダの3ファイル（K1〜K3）をアップロード
     （Describeタブの場合は、チャットボックスの「+」→「Upload images and files」）
  3. 追加したファイル名が一覧に表示されたことを確認
  4. （任意）「Only use specified sources」をオンにする
     → 検索が必要な質問では、指定したナレッジを優先して使う
        ※一般的なAI知識を完全には遮断できない（厳密な制御はCopilot Studio）
  5. テスト画面（Try it）で、ナレッジが回答に反映されるか確認する

 押さえておく仕様（Microsoft Learn「Add knowledge sources」より）
  ・アップロードできるファイル：.doc/.docx/.pdf/.ppt/.pptx/.txt は512MBまで、.xls/.xlsx は30MBまで
  ・アップロードできるファイル数：20ファイルまで（SharePoint／フォルダ／サイトは100ファイルまで）
  ・SharePoint／OneDriveは、既存のアクセス権と秘密度ラベルが尊重される
  ・アップロードしたファイルにアクセスできる人は、その内容にもアクセスできる点に注意
  ・新しく追加したSharePoint／OneDriveのファイルは「Preparing」と表示され、準備完了まで使われない
  ・Microsoft 365 GCC環境では、アップロードしたファイル（埋め込みファイル）は非対応

 テスト用プロンプト（ナレッジ）— 添付：demo_contract_v1_old.pdf / demo_contract_v2_new.pdf
  ① 「添付した2つのPDFを比較してください。1つ目が旧版、2つ目が新版です。
      そのうえで、ナレッジの契約審査ガイドラインに照らして、新版で基準から外れる点を表で示してください」
     → 期待：5件が基準外（正解は 03_デモ正解表 の「ガイドライン照合」参照）
  ② 「契約審査ガイドラインで、再委託の基準を教えてください」
     → 期待：「甲の事前の書面承諾を必須とする」（K1より）。PDFの添付なしでも答える
  ③ 「検収とは、社内ではどういう意味ですか？」
     → 期待：K3の定義（甲が納品物を確認して合否を通知すること）

■ B. スキルを追加する（約3分）
 手順（Configureタブ）
  1. 名前・説明・指示を入力した状態で、「Skills」を開く
  2. 「Add」を選び、skills フォルダの zip をアップロード
       ・pdf-diff-report.zip
       ・exec-summary-5lines.zip
  3. 名前と説明が正しく表示されたことを確認
  4. エラーが出たら、次を確認する
       ・ZIPの直下に SKILL.md があるか（フォルダごと圧縮すると入れ子になり、読み込めない場合がある）
       ・SKILL.md の先頭が、---で囲んだYAMLフロントマター（name と description）になっているか
       ・UTF-8のプレーンテキストか（リッチテキストや .txt 拡張子は不可）

 押さえておく仕様（Microsoft Copilot Camp「Skills in Agent Builder」より）
  ・スキル＝依頼がスキルの説明（description）に合うときだけ読み込まれる専門手順
  ・エージェントの「指示」＝常に読み込まれる共通ルール。短く保てる
  ・1つのエージェントに追加できるスキルは最大8個。ZIPは最大50MB
  ・SKILL.md 単体ではアップロードできない。必ずZIPにする
  ・プレビュー提供（Microsoft Frontier Program）。一般提供は近日予定とされている
    → 自分の環境に「Skills」が表示されるか、事前に必ず確認する

 テスト用プロンプト（スキル）— 「呼ばれる例」と「呼ばれない例」の両方で確認する
  スキル①：pdf-diff-report
   呼ばれる例：「添付した2つのPDFを比較してください。1つ目が旧版、2つ目が新版です」
     → 期待：要約／差分一覧（表）／影響と注意点／要確認事項 の4ブロックで出力
   呼ばれない例：「添付の契約書（新版）の第3条を、わかりやすく説明してください」
     → 期待：比較レポートの形式にならず、通常の説明になる
  スキル②：exec-summary-5lines
   呼ばれる例：（比較結果が出た後に）「この結果を経営層向けに5行で要約してください」
     → 期待：【結論】【最大の変更点】【影響】【リスク】【次のアクション】の5行のみ
   呼ばれない例：「比較結果を、Excelに貼れる表の形に整えてください」
     → 期待：5行要約にならず、表形式になる

■ C. 「指示」と「スキル」の使い分け（話すポイント）
  ・指示   ：役割・口調・やらないことなど、どの依頼でも守る共通ルール
  ・スキル ：特定の依頼のときだけ使う、詳しい手順や出力形式
  ・今回は、指示文を短く保ち、比較レポートの詳細な手順と形式はスキルに分けられる

■ D. うまくいかない場合
  ・「Skills」が表示されない → スライドの説明のみにする（無理にデモしない）。指示文だけでデモは成立する
  ・スキルが呼ばれない → descriptionを、実際の依頼の言い回しに近づけて直す
  ・ナレッジが反映されない → 「Preparing」表示でないか確認。少し待って再テスト
  ・ナレッジの内容を答えない → 質問に「ナレッジの契約審査ガイドラインに照らして」と明記して再テスト
